# 停笔位置判断

本技能解决"内容都有了，但不知道该在哪里结束"的方向类卡壳。有时文章已经说完该说的，但作者感觉"还没写完"；有时确实还缺东西，但不知道缺什么。本技能帮助判断文章的实际完成度，找到合理的停笔位置。

## Workflow

### 第一步：评估文章的完成度

阅读全文，对照文章核心意图检查：

| 检查项 | 是否完成 |
|-------|---------|
| 核心观点/主题是否已清晰表达 | 是 / 否 |
| 读者最关心的问题是否已回答 | 是 / 否 |
| 开篇提出的问题或悬念是否已处理 | 是 / 否 |
| 情感或思想是否已完成落脚 | 是 / 否 |
| 是否存在明显的逻辑断口 | 是 / 否 |

### 第二步：诊断卡壳原因

| 类型 | 表现 | 处理方向 |
|------|------|---------|
| 实际已完成 | 文章完整，作者出于不安全感不愿停笔 | 确认完成，给出停笔建议 |
| 结尾缺失 | 内容有了但没有收束，读者会感觉"没写完" | 建议使用 `ending-designer` |
| 内容确实不足 | 核心论点论证不完整，或有未处理的问题 | 指出缺口，建议补充后再停 |
| 过度延伸 | 已经说完，但作者还在加内容，导致文章越来越散 | 建议删除多余内容，在原有某处停笔 |

### 第三步：提供停笔建议

基于诊断，给出明确的建议：
- 如果可以停笔：指出最佳停笔位置（哪段或哪句话之后）
- 如果需要补充：说明还缺什么，补充完成后在哪里停
- 如果需要删减：指出哪些内容是多余的，删到哪里为止

### 第四步：输出结果

```
【停笔位置判断】
文章完成度评估：
　核心观点表达：[是/否]
　读者问题回答：[是/否]
　开篇悬念处理：[是/否]
　情感/思想落脚：[是/否]
　逻辑断口：[有/无]

诊断：[文章处于哪种状态]

建议：
　[停笔建议 / 补充建议 / 删减建议]

最佳停笔位置：[具体指出在哪里停，或说明需要先补充什么]
```

## Usage

提供全部已写内容，以及文章的核心意图（如不明确，本技能会先尝试反推）。

## Examples

### 示例 1：实际已完成但不敢停

**输入：**
> 文章：3000字的议论文，论证了"碎片化学习的局限性"，有三个分论点，有反驳，有结论段
> 困惑：感觉还没写完，想再加一段，但不知道加什么

**输出：**
```
【停笔位置判断】
文章完成度评估：
　核心观点表达：是（碎片化学习有系统性缺陷）
　读者问题回答：是（三个分论点覆盖了"为什么"）
　开篇悬念处理：是（结论段回扣了开篇）
　情感/思想落脚：是（有完整的结论）
　逻辑断口：无

诊断：文章实际已完成，继续加内容反而会稀释主题

建议：
　不建议再增加段落。"还没写完"的感觉通常来自对文章的熟悉——作者因为太了解这个话题，觉得自己说得不够。但对读者来说，这篇文章已经提供了完整的论证。如果一定要加，只建议在结论段最后加一句行动号召，不要新开段落。

最佳停笔位置：当前结论段的最后一句之后
```

### 示例 2：内容确实不足

**输入：**
> 文章：关于"如何在家自学编程"
> 已写内容：选什么语言（Python）、找什么资源（几个网站）、就这两块，然后不知道还要写什么

**输出：**
```
【停笔位置判断】
文章完成度评估：
　核心观点表达：是（Python入门 + 资源推荐）
　读者问题回答：否（读者最关心的"然后呢？学完资源怎么练？多久能学会？"没有回答）
　开篇悬念处理：需要确认开篇
　情感/思想落脚：否（没有结束感）
　逻辑断口：有（推荐完资源就停了，缺少"如何有效使用这些资源"的实操指导）

诊断：内容确实不足，文章在最关键的"怎么学"环节缺失

建议：
　补充以下内容后再停笔：
　1. 如何制定学习计划（每天多长时间，按什么顺序）
　2. 如何从学到用（做什么练手项目）
　3. 遇到卡壳怎么办（解决学习中断的问题）

最佳停笔位置：补充上述三点之后，加一段简短总结，然后停笔
```

## Best Practices

- "不知道在哪里停"有时是完美主义的变体，要先判断是内容问题还是心理问题，不能一律建议继续写。
- 指出"可以停了"需要有充分依据，不能只是安慰作者。
- 如果诊断是"过度延伸"，要明确指出哪些段落是多余的，不能含糊说"删一些"。

## Edge Cases

- **作者提供的内容非常短（不足300字）**：直接判断"内容不足"，帮助识别还缺哪些主要内容。
- **文章类型是散文或日记**：完成度标准不同，更看重情感是否落脚，不看论点是否完整。
- **作者说"不知道文章的核心是什么"**：先用 `purpose-clarifier` 或 `theme-retriever` 确认核心，再判断完成度。
