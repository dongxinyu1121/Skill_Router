# 写作质量评估

本技能解决"自我怀疑"类卡壳：作者感觉写得很糟糕，但说不清楚哪里有问题，陷入模糊的自我否定。本技能通过对已写内容进行客观评估，区分"真正的问题"和"完美主义焦虑"，给出有针对性的诊断。

## Workflow

### 第一步：初步评估整体质量

从五个维度快速扫描：

| 维度 | 评估标准 |
|------|---------|
| 内容完整性 | 该说的有没有说，有没有明显缺漏 |
| 逻辑清晰度 | 论点或叙述是否有清晰的脉络 |
| 表达准确性 | 意思有没有说清楚，有没有歧义 |
| 语言流畅度 | 读起来是否顺畅，有没有别扭的句子 |
| 风格一致性 | 语气是否统一，有没有明显断层 |

### 第二步：区分问题类型

| 类型 | 说明 | 处理方式 |
|------|------|---------|
| 真实问题 | 内容或逻辑确实有缺陷 | 明确指出，给出修改方向 |
| 表达问题 | 意思对但表达不够好 | 指出，说明这是可以修改的细节 |
| 完美主义焦虑 | 文章实际没问题，但作者自我评分过低 | 明确告知，给出客观评价 |
| 风格偏好问题 | 技术上没错，只是作者自己不喜欢这种风格 | 区分"客观质量"和"个人偏好" |

### 第三步：给出评估结论

避免"很好啊""没问题"这种空洞的安慰，也避免"到处都是问题"的全面否定。给出具体的、有依据的评估。

### 第四步：输出结果

```
【写作质量评估】
整体评估：[一句话概括当前质量水平]

各维度评分（✓ 达标 / △ 有改善空间 / ✗ 需要重点处理）：
　内容完整性：[✓/△/✗] — [一句话说明]
　逻辑清晰度：[✓/△/✗] — [一句话说明]
　表达准确性：[✓/△/✗] — [一句话说明]
　语言流畅度：[✓/△/✗] — [一句话说明]
　风格一致性：[✓/△/✗] — [一句话说明]

真正的问题（需要处理）：
1. [具体问题 + 位置 + 修改建议]
2. [具体问题 + 位置 + 修改建议]（如有）

可以暂时不管的：
[哪些"问题"其实不是问题，或者可以留到最后再处理]

结论：[对自我怀疑情绪的客观回应——文章真的很糟糕，还是作者太严格了]
```

## Usage

提供觉得"写得很烂"的内容，以及你主要的不满意点（如果能说清楚的话）。

## Examples

### 示例 1：实际没有大问题

**输入：**
> 我写了一篇关于早起习惯的文章，感觉写得很糟糕，不知道哪里不对，就是读起来别扭

**输出：**
```
【写作质量评估】
整体评估：文章内容完整，逻辑清晰，主要问题集中在表达层面，属于可修改的细节，不是结构性问题

各维度评分：
　内容完整性：✓ — 早起的好处、如何建立习惯都有覆盖，无明显缺漏
　逻辑清晰度：✓ — 从"为什么"到"怎么做"的结构清晰
　表达准确性：△ — 有几处意思模糊，但不影响整体理解
　语言流畅度：△ — 约30%的句子有轻微别扭感，主要是句式过于相似
　风格一致性：✓ — 语气统一，没有明显断层

真正的问题（需要处理）：
1. 句式单调：全文大量使用"首先…其次…然后…"的结构，读起来像教科书，建议用 `sentence-diversifier` 处理
2. 第三段第二句话意思不够清楚："早起需要坚持"——坚持什么？怎么坚持？这句话需要具体化

可以暂时不管的：
个别用词不够精准——这在草稿阶段完全正常，最后校对时再处理即可

结论：文章没有你以为的那么糟。你感觉到的"别扭"主要来自句式单调，这是很容易修复的表达问题，不是内容问题。建议先把全文写完，再来统一处理句式。
```

### 示例 2：真的有问题

**输入：**
> 我写了一篇关于远程工作的议论文，感觉哪里不对

**输出：**
```
【写作质量评估】
整体评估：文章有一个真实的结构性问题——论点和论据之间存在明显的逻辑跳跃，这会影响说服力

各维度评分：
　内容完整性：△ — 三个分论点中第二个展开不足，只有论点没有论据
　逻辑清晰度：✗ — 第四段的论据（"员工满意度调查"）和论点（"远程工作提升效率"）关联不紧密，满意度不等于效率
　表达准确性：✓ — 意思清楚，表达准确
　语言流畅度：✓ — 语言流畅，句式有变化
　风格一致性：✓ — 全文风格统一

真正的问题（需要处理）：
1. 第二分论点缺乏论据：只写了"远程工作减少通勤时间"，但没有说这对效率有什么影响，需要补充数据或案例
2. 第四段逻辑跳跃：员工满意度高≠工作效率高，需要补充说明两者之间的关联，或换一个更直接支持效率论点的论据

可以暂时不管的：
开头的例子稍显老套，但不影响论证，可以最后再换

结论：你的直觉是对的，文章确实有问题，但问题是具体的、可以修复的——主要是论证层面，而不是整体结构。建议用 `logic-bridge` 处理第四段的逻辑跳跃。
```

## Best Practices

- 不做空洞的安慰（"写得很好啊"），也不做全面否定（"到处都是问题"）；客观评估的价值在于精准指出问题所在。
- 区分"真正的问题"和"作者的自我怀疑"——两种情况需要完全不同的回应。
- 如果文章确实有问题，在给出评估后，要指向对应的专项技能处理具体问题。

## Edge Cases

- **文章非常糟糕但作者情绪脆弱**：诚实但有建设性地指出问题，聚焦"怎么修"而不是"有多糟"。
- **作者不断追问"你觉得我写得怎么样"**：明确说明本技能只提供客观维度评估，不做主观评分；审美判断没有绝对标准。
- **文章类型无法判断**：先询问文章类型和写作目的，再进行评估。
