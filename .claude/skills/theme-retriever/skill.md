# 主题找回

本技能解决"写着写着忘了自己要说什么"的方向类卡壳。通过分析已写内容，帮助作者识别主题漂移的位置，找回文章的核心主线。

## Workflow

### 第一步：提取文章的原始意图

从以下来源判断文章最初想说什么：
- 文章标题（如有）
- 开篇段落的核心论点或触发事件
- 作者补充说明的写作目的

### 第二步：梳理已写内容的实际走向

逐段分析已写内容：
- 每段的核心话题是什么
- 与原始意图的关联程度：紧密 / 相关 / 游离 / 无关

### 第三步：识别漂移位置和原因

| 漂移原因 | 表现 |
|---------|------|
| 举例过度展开 | 一个例子展开了太多，变成了主角 |
| 话题联想跑偏 | 从A联想到B，从B联想到C，越走越远 |
| 论点替换 | 写着写着换成了另一个观点，原来的反而没论证完 |
| 情绪带跑 | 写到某个话题有感触，开始大段抒情，偏离了原有框架 |

### 第四步：输出结果

```
【主题找回分析】
原始意图：[文章最初想说的是什么]
当前实际走向：[文章现在实际在说什么]
核心主线：[用一句话重新锚定文章应该围绕的核心]

漂移位置：[从第几段/哪个话题开始偏离]
漂移原因：[为什么会漂移]

处理建议：
　保留：[哪些内容与主线一致，应该保留]
　调整：[哪些内容游离，可以压缩或删除]
　补充：[主线上还缺少哪些内容]

追问：[如果原始意图不明确，提出最关键的一个问题]
```

## Usage

提供全部已写内容，以及文章标题或最初的写作目的。本技能自动分析漂移情况。

## Examples

### 示例 1：举例过度展开

**输入：**
> 文章标题：《为什么我们越来越不擅长无聊》
> 已写内容：第一段讲手机让人逃避无聊→第二段开始讲手机的历史→第三段讲乔布斯→第四段讲苹果公司的商业模式

**输出：**
```
【主题找回分析】
原始意图：探讨现代人丧失了与"无聊"共处的能力，以及这背后的原因
当前实际走向：从手机说到手机的历史，再到乔布斯和苹果商业模式，已经变成了科技史文章
核心主线：手机（和类似工具）如何系统性地剥夺了人们体验无聊的机会

漂移位置：第二段开始，"手机的历史"偏离了主线
漂移原因：从"手机让人逃避无聊"联想到"手机是什么"，陷入了背景介绍的惯性

处理建议：
　保留：第一段（建立核心论点）
　调整：第二至四段大幅压缩，只保留和"为什么手机让人无法无聊"直接相关的部分（如：推送机制、算法设计）；乔布斯和商业模式可以只用一句话带过或删除
　补充：为什么"无聊"其实有价值（创意、自我认知）；如何在手机时代重新学会无聊

追问：无
```

### 示例 2：原始意图不明确

**输入：**
> 没有标题
> 已写内容：第一段写了失眠，第二段写了夜晚城市的样子，第三段写了工作压力，第四段写了和朋友的一段对话

**输出：**
```
【主题找回分析】
原始意图：不明确——已写内容涉及失眠、城市、压力、人际关系四个话题，尚无明确主线
当前实际走向：四段各自独立，目前像是素材积累而非成形的文章
核心主线：待确认

漂移位置：无法判断，因为主线尚未建立
漂移原因：可能是作者在写作过程中意图发生了变化，或本来就是在探索阶段

处理建议：先回答追问，再确认主线，再决定每段的去留

追问：这篇文章写完后，你希望读者记住的是哪一件事？（A）失眠这件事本身；（B）城市生活的疏离感；（C）工作压力对人的影响；（D）某种关于孤独或连接的感悟
```

## Best Practices

- 漂移不一定是坏事——有时"跑偏"的方向比原来的更有价值，此时建议作者考虑是否干脆改变文章主题。
- 不替作者决定"哪些段落该删"，只指出哪些段落游离于主线，删留由作者决定。
- 主线找回后，建议配合 `outline-expander` 补充主线上缺失的内容。

## Edge Cases

- **作者本来就想写发散的文章（如意识流）**：主题漂移可能是刻意的，需先确认文章类型再判断。
- **文章太短，只有一两段**：无法判断漂移，建议作者继续写，写到 400 字以上再来分析。
- **主题本身过于宏大**：提示作者收窄主题，一篇文章只能说好一件事。
