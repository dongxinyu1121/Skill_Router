# 写作密度检查

本技能解决"某一部分展开太细，后面不知道怎么收"的节奏类卡壳。当某段内容"写跑了"，占据了过多篇幅，导致整体节奏失控，本技能帮助识别问题位置，提供缩减或调整方向。

## Workflow

### 第一步：分析文章的密度分布

将已写内容按段落/部分划分，评估每个部分的：
- **信息密度**：这部分传达了多少有效信息
- **篇幅占比**：这部分用了多少文字
- **重要性权重**：这部分对核心主题的贡献有多大

理想的密度分布应该与重要性权重成正比——重要的内容应该有更多篇幅，次要的内容应该简短。

### 第二步：识别密度失控位置

| 问题类型 | 表现 |
|---------|------|
| 次要内容过度展开 | 一个支撑性的例子写了几百字，喧宾夺主 |
| 开头过长 | 背景铺垫占据了文章1/3以上的篇幅 |
| 某分论点/情节过度细化 | 技术性细节、过程描述超出读者需要 |
| 感情抒发失控 | 情绪段落不断延伸，偏离了文章节奏 |

### 第三步：提供调整建议

针对过度展开的部分，给出具体的处理方向：

| 处理方式 | 适用场景 |
|---------|---------|
| 大幅压缩 | 这部分内容可以用更少的文字表达同样的意思 |
| 改为概括式叙述 | 用一句话概括，不需要展开细节 |
| 移到附录或脚注 | 内容有价值但不在主线上，不宜放正文 |
| 独立成篇 | 这个话题值得单独写，但不适合放在这篇文章里 |
| 删除 | 这部分对核心主题贡献不足，可以删去 |

### 第四步：输出结果

```
【写作密度分析】
各部分密度评估：
　[部分1]：篇幅 [X字] / 重要性 [高/中/低] / 状态 [正常/偏重/偏轻]
　[部分2]：篇幅 [X字] / 重要性 [高/中/低] / 状态 [正常/偏重/偏轻]
　[部分N]：...

密度失控位置：[哪个部分展开过度]
失控原因：[为什么这里会写多]

处理建议：
　[具体处理方式] — [哪些内容可以保留，哪些可以删减]
　建议目标篇幅：[这个部分压缩到大约多少字比较合适]

压缩后的整体节奏：[调整后文章的结构会变得怎样]
```

## Usage

提供全部已写内容，并说明文章的预期总篇幅或类型。

## Examples

### 示例 1：例子写跑了

**输入：**
> 文章是关于"数字断联的好处"，总计划1500字
> 目前：引言200字→分论点1（效率提升）100字→举了一个程序员关掉手机工作的例子，写了700字→后面还有两个分论点没写

**输出：**
```
【写作密度分析】
各部分密度评估：
　引言：200字 / 重要性 中 / 状态 正常
　分论点1论述：100字 / 重要性 高 / 状态 偏轻（核心论点只用了100字）
　分论点1例子：700字 / 重要性 低-中 / 状态 严重偏重（例子比论点本身多7倍）
　分论点2、3：待写

密度失控位置：分论点1的举例段落（700字）
失控原因：例子本身的故事性强，展开过程中不自觉地进入了叙事模式，偏离了"举例论证"的功能

处理建议：
　大幅压缩 — 这个例子最多需要150字：说清楚"谁做了什么"和"结果是什么"，细节过程可以删除
　建议目标篇幅：将这个例子压缩到100-150字
　可以保留：这个程序员案例的核心——关掉手机后完成了什么任务、效率提升了多少（如果有数据更好）
　可以删除：他如何说服自己关手机的心理过程、当天的工作环境描写、其他无关细节

压缩后的整体节奏：引言200字→论点1（150字+例子150字）→论点2（200字）→论点3（200字）→结尾150字，共约1050字，留有余地
```

### 示例 2：开头铺垫太长

**输入：**
> 文章是关于"为什么要学一门外语"
> 目前写了900字，全是语言学习的历史背景和各国语言政策，还没有进入正题

**输出：**
```
【写作密度分析】
各部分密度评估：
　背景铺垫：900字 / 重要性 低 / 状态 严重偏重
　核心论述：0字 / 重要性 高 / 状态 缺失

密度失控位置：整个已写部分（全是铺垫，正题未开始）
失控原因：从"宏观背景"切入主题是常见的写作策略，但这里的宏观展开过于充分，读者在看到核心论点之前会失去耐心

处理建议：
　大幅压缩 — 背景铺垫最多200字足够，剩余700字基本可以删除
　可以保留的方向：选一个最有冲击力的背景数据或事实（如全球X亿人会说第二语言），用一句话带出即可
　可以删除：各国语言政策的详细介绍、历史演变过程
　另一种方案：完全跳过宏观背景，直接从一个个人场景或问题切入（建议使用 section-opener）

压缩后的整体节奏：开篇引入（200字）→核心论点展开（1000-1500字）→结尾（200字）
```

## Best Practices

- 密度分析要结合文章类型：学术文章允许更高的信息密度；公众号文章节奏要更快，读者耐心有限。
- 压缩建议要具体指出"删什么"，不能只说"写少点"。
- 如果某个展开过度的部分内容本身很好，建议作者保存下来，考虑单独成文。

## Edge Cases

- **作者不确定预期篇幅**：先问清楚，不同篇幅目标对应完全不同的密度标准。
- **全文密度都很低（水很多）**：建议使用 `proportion-balancer` 进行全局比例调整。
- **展开过度的部分恰好是文章精华**：调整策略，把其他部分压缩，以该部分为核心重新规划结构。
