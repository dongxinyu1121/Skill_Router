# 写作目的澄清

本技能解决"不知道这篇文章为什么要写、写给谁看"的方向类卡壳。写作目的不清晰会导致作者在每个细节上都拿不定主意。通过澄清读者和目的，重建写作方向感。

## Workflow

### 第一步：从已写内容反推写作意图

阅读已写内容，尝试回答：
- 这篇文章在帮助读者做什么（理解某件事 / 相信某个观点 / 感受某种情绪 / 学会某种方法）
- 隐含的读者画像是什么（从词汇深度、举例方式、假设的背景知识判断）

### 第二步：识别目的模糊的症状

| 症状 | 表现 |
|------|------|
| 读者混乱 | 同一篇文章里，一段假设读者是专家，另一段假设读者什么都不懂 |
| 目的摇摆 | 有时像在说服，有时像在分享，有时像在解释，三种目的混在一起 |
| 深浅失控 | 某些概念解释得极详细，另一些又完全跳过，缺乏一致标准 |
| 无法决策 | 每写一段都在纠结"这个要不要写""这里该深还是该浅" |

### 第三步：帮助作者澄清

通过一组追问，帮助作者确认：

**关于读者：**
- 这篇文章理想中是谁在读？（年龄、背景、关心什么）
- 读者在读这篇文章之前，对这个话题知道多少？

**关于目的：**
- 读者读完这篇文章，你希望他们做什么 / 感受什么 / 相信什么？
- 如果读者只能记住一件事，你希望是哪件？

### 第四步：输出结果

```
【写作目的澄清】
从已写内容反推的读者：[描述]
从已写内容反推的目的：[描述]
诊断到的问题：[目的模糊的具体症状]

建议明确的读者定位：[一句话描述理想读者]
建议明确的写作目的：[完成以下句子："读者读完之后，应该能___"]

对已写内容的影响：
　需要调整的段落：[哪些段落和明确后的读者/目的不匹配]
　方向建议：[如何调整]

追问：[帮助作者确认读者和目的的最关键问题]
```

## Usage

提供已写内容，并描述你原本打算写这篇文章的原因（哪怕只是一句话）。

## Examples

### 示例 1：读者定位混乱

**输入：**
> 文章主题：介绍区块链技术
> 困惑：写着写着不知道该讲多深，有时候解释得太简单了，有时候又太专业

**输出：**
```
【写作目的澄清】
从已写内容反推的读者：模糊——既有"区块链是一种分布式账本"这样的基础解释，又有"共识机制的拜占庭容错性"这样的专业表述
从已写内容反推的目的：科普（但深浅标准不一致）
诊断到的问题：读者定位在"完全不懂的普通人"和"有技术背景的读者"之间反复横跳

建议明确的读者定位：对区块链感兴趣但没有技术背景的普通人（比如听说过比特币但不懂原理的人）
建议明确的写作目的：读者读完之后，应该能用自己的话向朋友解释"区块链是什么，为什么它很难被篡改"

对已写内容的影响：
　需要调整的段落：所有出现"拜占庭容错""哈希函数""P2P网络"等术语的地方，要么删除，要么用类比解释
　方向建议：统一使用非技术类比（如"区块链就像一本每个人都有副本的账本"），不需要解释原理，只需要解释效果

追问：你身边有没有一个完全不懂技术但很聪明的朋友？这篇文章是为了让他读懂，还是为了让已经懂一点的人更懂？
```

### 示例 2：写作目的摇摆

**输入：**
> 文章主题：关于"慢生活"
> 已写内容：既有对现代人太忙的批判，又有教读者如何放慢节奏的建议，还有对自己慢生活经历的描述

**输出：**
```
【写作目的澄清】
从已写内容反推的读者：关注生活方式、有一定阅读习惯的都市人
从已写内容反推的目的：三种目的混合——批判、教程、个人分享
诊断到的问题：写作目的摇摆导致文章结构松散，读者不知道这篇文章的立场是"我来说服你"还是"我来告诉你怎么做"还是"我来和你分享"

建议明确的读者定位：感到生活节奏太快、想做出改变但不知道从哪开始的都市人
建议明确的写作目的：读者读完之后，应该能理解为什么慢下来是值得的，并获得一个可以立刻尝试的具体方法

对已写内容的影响：
　需要调整的段落：批判部分可以作为铺垫保留，但压缩到1段以内；个人经历作为案例保留，但服务于"为什么值得"的论证；教程部分聚焦最重要的1-2个方法，不要写成清单
　方向建议：确定"说服+实操"的双目的，按"为什么→怎么做→你也可以"的结构重新梳理

追问：无
```

## Best Practices

- 目的澄清不是批评作者"想太多"，而是帮助建立决策标准——有了清晰的读者和目的，后续每个段落的取舍都变得容易。
- 有时候作者本来就想写多目的的文章，此时建议说明多目的并存的前提条件（结构要更清晰，分段要更明确）。
- 目的确认后，建议配合 `outline-expander` 重新梳理文章结构。

## Edge Cases

- **作者说"就是随便写写，没有目的"**：对于日记或练笔，目的澄清不适用；如果是要发表的文章，则建议作者考虑读者体验。
- **文章目的和读者都非常清晰，但还是卡壳**：目的不是问题，建议返回 `writing-diagnose` 重新判断卡壳类型。
- **作者想同时说服多个完全不同的读者群**：建议写多篇而非一篇，不同读者需要不同切入点。
