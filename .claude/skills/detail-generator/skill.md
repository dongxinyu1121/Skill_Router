# 细节补充

本技能解决"内容太干、太空洞"的素材卡壳。当作者写的内容读起来像提纲，缺乏血肉，不知道该补充什么具体内容，本技能帮助识别缺少哪类细节，并给出补充方向。

## Workflow

### 第一步：理解段落目的

读取需要补充细节的段落，判断这段话的写作目的：

| 目的 | 说明 |
|------|------|
| 说服 | 需要论据支撑，读者要被说服相信某件事 |
| 说明 | 需要清晰解释，读者要理解某个概念或过程 |
| 渲染氛围 | 需要感官细节，读者要产生身临其境的感受 |
| 建立情感共鸣 | 需要情绪细节，读者要感同身受 |
| 提供操作指导 | 需要步骤和具体数字，读者要知道怎么做 |

### 第二步：诊断缺少哪类细节

根据段落目的，对照细节类型进行诊断：

| 细节类型 | 适合目的 | 具体形式 |
|---------|---------|---------|
| 感官细节 | 渲染氛围 | 视觉、听觉、触觉、嗅觉、味觉的具体描述 |
| 数据细节 | 说服、说明 | 数字、百分比、研究结论、时间节点 |
| 案例细节 | 说服 | 真实事件、人物经历、新闻案例 |
| 对比细节 | 说服、说明 | 前后对比、横向比较、正反对比 |
| 过程细节 | 说明、操作指导 | 步骤分解、时序描述、原因链条 |
| 情绪细节 | 建立共鸣 | 内心活动、情感变化、心理描写 |
| 对话细节 | 渲染氛围、建立共鸣 | 真实或虚构的对话片段 |

### 第三步：提供补充建议

给出 3-5 条具体补充方向，每条包含：
- **细节类型**
- **补充方向**：告诉作者去哪里找或怎么想
- **示例**：如能直接给出则提供，否则描述方向

### 第四步：输出结果

```
【细节补充建议】
段落目的：[这段话想让读者感受/理解/相信什么]
缺少的细节类型：[诊断结果]

建议 1：[细节类型] — [补充方向]
　示例："[具体示例或方向描述]"

建议 2：[细节类型] — [补充方向]
　示例："[具体示例或方向描述]"

建议 3：[细节类型] — [补充方向]
　示例："[具体示例或方向描述]"

建议 4：[细节类型] — [补充方向]（可选）
建议 5：[细节类型] — [补充方向]（可选）

注意：[如果段落本身有其他问题，在此说明]
```

## Usage

提供需要补充细节的段落，并说明这段话在文章中的目的（说服/说明/渲染/共鸣/操作）。

## Examples

### 示例 1：议论文论据不足

**输入：**
> 段落目的：说服读者重视睡眠
> 段落内容：睡眠对健康非常重要，睡眠不足会导致很多问题，现代人普遍睡眠不够，这值得我们重视。

**输出：**
```
【细节补充建议】
段落目的：说服读者认识到睡眠不足的严重性
缺少的细节类型：数据细节、案例细节（目前全是泛泛而谈，无任何具体支撑）

建议 1：数据细节 — 睡眠不足的具体健康影响数据
　示例："研究表明，连续17小时不睡觉的认知损伤相当于血液酒精浓度0.05%"

建议 2：数据细节 — 现代人睡眠现状数据
　示例："2023年中国睡眠研究报告显示，超过3亿中国人存在睡眠障碍"

建议 3：案例细节 — 因睡眠不足导致严重后果的真实事件
　示例：切尔诺贝利核事故、挑战者号爆炸等被研究证实与人员疲劳有关的案例

建议 4：对比细节 — 充足睡眠vs睡眠不足的具体表现对比
　示例：同一人在睡足8小时和睡5小时后的反应测试结果对比

注意：当前段落逻辑上没有问题，但缺乏任何实质性支撑，说服力接近于零。
```

### 示例 2：散文场景感不足

**输入：**
> 段落目的：渲染氛围——让读者感受到老街市场的热闹
> 段落内容：那个早市很热闹，有很多摊位，卖各种各样的东西，很多人在买东西。

**输出：**
```
【细节补充建议】
段落目的：渲染老街早市的热闹氛围，让读者身临其境
缺少的细节类型：感官细节（视觉/听觉/嗅觉全部缺失）、对话细节

建议 1：听觉细节 — 市场的声音层次
　示例："卖鱼的老伯扯着嗓子喊，隔壁榨甘蔗的机器轰鸣，中间夹着几声婴儿啼哭"

建议 2：嗅觉细节 — 混合气味
　示例："刚出炉的油条香和隔壁活鱼桶的腥气混在一起，反而闻着亲切"

建议 3：视觉细节 — 具体的人物动作而非"很多人"
　示例："一个穿睡衣的女人夹着菜篮子，侧着身子从两个摊位之间挤过去"

建议 4：对话细节 — 一两句摊贩和顾客的对话
　示例："'今天的豆腐新不新鲜？'——'新鲜！五点就到货的！'"

注意：无
```

## Best Practices

- 细节补充的目的是服务段落目标，不是为了丰富而丰富——每条建议都要说明"为什么这个细节有用"。
- 不替作者写完整段落，只提供"原料"和方向，让作者选择最符合自己感受的细节来填充。
- 对于议论文，优先建议有据可查的数据和案例；对于文学性文章，优先建议来自作者自身经验的感官细节。

## Edge Cases

- **作者不知道段落目的是什么**：先追问"你希望读者读完这段之后有什么感受或想法"，再进行诊断。
- **段落本身逻辑有问题**：在"注意"中指出，建议先用 `argument-builder` 或 `contradiction-resolver` 处理逻辑，再补充细节。
- **作者要求直接写细节**：告知本技能只提供方向，具体细节应由作者基于自身知识和经验选取，以保持文章的真实性。
