# 打破完美主义

本技能解决"同一段反复改，改到不敢往下写"的情绪类卡壳。完美主义不是态度问题，而是一种让写作陷入死循环的思维模式。本技能帮助识别完美主义的触发点，并提供切实可行的打破策略。

## Workflow

### 第一步：识别完美主义的表现

| 表现 | 本质 |
|------|------|
| 同一段改了五遍以上 | 没有明确的"足够好"标准 |
| 改完之后还是不满意，再改回去 | 在多个版本之间循环，没有向前推进 |
| 总觉得这段写完才能写下一段 | 线性完美主义——拒绝"先完成再完善" |
| 越改越不知道哪个版本好 | 失去判断能力，需要外部标准 |
| 害怕写下一段，因为还没准备好 | 完美主义已扩展到未知领域 |

### 第二步：建立"足够好"标准

帮助作者在修改中建立可操作的标准，而不是追求不存在的"最好"：

**功能性标准：**
- 这段话有没有说清楚它要说的事？
- 读者能不能理解这里的意思？
- 它和上下文的衔接是否自然？

如果三个问题都是"是"，这段话就足够好，可以继续写了。

### 第三步：提供打破僵局的具体策略

根据作者的具体表现，选择最合适的策略：

**策略A：锁定草稿，向前推进**
给自己设定规则：这段话今天不再改。哪怕它不够好，先写完整篇文章，再回头统一修改。完成的草稿比完美的片段更有价值。

**策略B：设置修改上限**
每段话最多改三次。到了第三次，选一个版本，不管是否满意，继续往下写。

**策略C：写"垃圾草稿"**
给自己明确的权限：接下来写的这一段，允许是垃圾。不考虑文笔，不考虑逻辑，就是把想说的意思倒出来。垃圾草稿可以改，但空白什么都改不了。

**策略D：换时间再看**
完全离开这段文字24小时，再来看。时间会给你新的视角，你会发现它没有你以为的那么糟，或者你会清楚地知道改哪里。

### 第四步：输出结果

```
【打破完美主义】
当前表现：[具体的完美主义症状]
根本问题：[没有标准 / 线性思维 / 能力焦虑]

足够好的标准（对当前这段）：
　□ 这段说清楚了它要说的事
　□ 读者能理解这里的意思
　□ 和上下文衔接自然

推荐策略：[策略名称]
具体操作：[怎么做，分步骤说明]

立刻做的一件事：[最小的一个动作，帮助跨出第一步]
```

## Usage

描述你在哪里卡住了（改了多久、改了几遍、什么感觉），以及当前反复修改的那段内容。

## Examples

### 示例 1：同一段反复修改

**输入：**
> 我的开头段已经改了七八遍了，每次改完都觉得还不对，但不改又不舒服，现在完全不敢写后面的内容了

**输出：**
```
【打破完美主义】
当前表现：开头段反复修改超过7次，在多个版本之间循环，且已扩展至对全文的恐惧
根本问题：没有"足够好"的标准，且存在线性完美主义（拒绝在开头不完美的情况下继续）

足够好的标准（对当前的开头段）：
　□ 这段说清楚了文章要讨论的话题
　□ 读者能知道接下来会读到什么
　□ 第一句话有足够的吸引力让人继续读

推荐策略：锁定草稿，向前推进
具体操作：
1. 在当前七八个版本中，随机选一个（真的随机，不要再评判）
2. 把其他版本复制到文档末尾（不要删掉，这样你不会有"彻底失去它们"的焦虑）
3. 在选定的版本下面写"【暂定，后续再改】"
4. 现在开始写第二段，不要回头看第一段
5. 等全文完成后，再统一处理所有暂定的地方

立刻做的一件事：打开文档，选一个版本，复制其他版本到末尾，然后滚动到第一段之后，开始打第一个字。
```

### 示例 2：总觉得没准备好

**输入：**
> 我有很多想法，但总觉得想清楚了才能开始写，结果一直在"准备"，根本没有写出东西来

**输出：**
```
【打破完美主义】
当前表现：用"还没想清楚"作为不开始写的理由，进入无限准备循环
根本问题：把"想清楚"当作写作的前提条件，但实际上写作本身就是想清楚的过程

足够好的标准（不适用，因为目前连草稿都没有）

推荐策略：写"垃圾草稿"
具体操作：
1. 打开一个新文档，标题写"草稿（垃圾，不算数）"
2. 设置一个15分钟的计时器
3. 在这15分钟里，把所有关于这个话题的想法写出来——不管顺序、不管文笔、不管逻辑
4. 计时器响了，停笔，看看你写了什么
5. 你会发现：你其实比你以为的想得更多，你只是没有"开始"的勇气

立刻做的一件事：现在打开新文档，写下关于这个话题你最想说的一句话，哪怕很烂。
```

## Best Practices

- 不要告诉作者"完美主义没关系，慢慢来"——这等于什么都没说。要给出可以立刻执行的具体动作。
- "锁定草稿"策略需要真正的执行——帮助作者设定一个物理上的截断点（把其他版本挪到末尾、关掉对应文档）。
- 有时完美主义背后是对"被评判"的恐惧，此时需要提醒作者：草稿阶段没有观众，只有作者自己。

## Edge Cases

- **作者的文章真的写得不好（不只是完美主义）**：先用 `quality-assessor` 做客观评估，再决定是完美主义还是真的需要修改。
- **有明确截止日期**：直接说明时间限制，推荐"设置修改上限"策略，优先完成而非完美。
- **作者说"就是要写完美才发表"**：尊重这个目标，但帮助分解：先完成全文草稿，再做统一精修，而不是每段达到完美再往下写。
