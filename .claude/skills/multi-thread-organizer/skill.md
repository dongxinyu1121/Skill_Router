# 多线整合

本技能解决"有好几个想写的话题，但不知道怎么把它们放进同一篇文章"的整合类卡壳。通过分析各话题之间的逻辑关系，找到能将多线索组织成一篇文章的结构方案。

## Workflow

### 第一步：梳理各话题之间的关系

列出所有子话题，判断它们之间是什么关系：

| 关系类型 | 说明 | 整合方式 |
|---------|------|---------|
| 并列关系 | 多个话题是同一主题的不同维度 | 选一个主题词统领，各话题作为分论点 |
| 递进关系 | 话题A是话题B的基础，话题B是话题C的深化 | 按递进顺序排列，前后自然衔接 |
| 因果关系 | 某些话题是原因，某些是结果 | 原因在前，结果在后，或先说结果再追溯原因 |
| 对比关系 | 话题之间形成对照 | 交替或对比呈现，强化差异 |
| 无明显关系 | 话题之间缺乏内在联系 | 需要找到一个共同的上层主题，或拆开写多篇 |

### 第二步：寻找统一线索

如果多个话题没有明显关系，尝试以下方法找到统一线索：

- **主题法**：这些话题背后有没有共同的核心主张或情感？
- **人物法**：这些话题可不可以通过同一个人物或视角串联？
- **时间法**：这些话题可不可以按照时间顺序排列？
- **问题法**：这些话题可不可以都是对同一个问题的回答？

### 第三步：提供整合结构方案

给出 2-3 种不同的整合结构，每种方案说明：
- 统一线索是什么
- 各话题在结构中的位置
- 话题之间如何过渡

### 第四步：输出结果

```
【多线整合方案】
各话题：[列出所有子话题]
话题间的关系：[关系类型分析]
统一线索（建议）：[什么可以将所有话题串在一起]

方案 A（[结构类型]）：
　统一线索：[是什么]
　结构顺序：
　　1. [话题X]
　　2. [话题Y]
　　3. [话题Z]
　过渡策略：[话题之间怎么连接]

方案 B（[结构类型]）：
　（同上格式）

推荐：方案 [X]，因为[一句话]
注意：[如果某个话题与其他话题实在无法整合，建议单独成文]
```

## Examples

### 示例 1：有内在关系但没想清楚

**输入：**
> 想写的话题：
> A. 现代人越来越不会做饭
> B. 外卖让人失去了对食物的感受
> C. 做饭是一种情绪管理方式
> D. 独居生活和吃饭的关系

**输出：**
```
【多线整合方案】
各话题：A（不会做饭）/ B（外卖与感受）/ C（做饭与情绪）/ D（独居与吃饭）
话题间的关系：并列+因果混合——A和B是"问题描述"，C是"做饭的价值"，D是一个特定的生活场景
统一线索（建议）："吃饭"背后是一个关于"自我关照"的主题——我们如何对待食物，折射了我们如何对待自己

方案 A（递进结构：问题→原因→价值→出路）：
　统一线索：从"我们失去了什么"到"我们可以找回什么"
　结构顺序：
　　1. B（外卖让我们失去了对食物的感受）——建立"失去了什么"的问题
　　2. A（现代人越来越不会做饭）——扩展问题的范围
　　3. D（独居与吃饭）——具体化到一种生活状态中
　　4. C（做饭是情绪管理）——提出价值，给出"为什么值得找回来"
　过渡策略：每个话题用"于是"或"然而"自然递进，最后C作为全文的落脚点

方案 B（对比结构：两种生活方式的对比）：
　统一线索：以"做饭的人"和"不做饭的人"作为两个对照视角
　结构顺序：
　　先写"外卖时代的生活"（B+A+D的一侧）
　　再写"做饭改变了什么"（C+D的另一侧）
　过渡策略：用一个转折句分隔两种生活

推荐：方案 A，因为这四个话题天然有递进逻辑，按照"问题-价值"排列更有说服力
注意：D（独居与吃饭）和其他话题的关联相对弱，写作时注意让它服务于统一线索，不要独立展开太多
```

### 示例 2：话题之间无明显关系

**输入：**
> 想在同一篇文章里写：旅行、读书、养猫

**输出：**
```
【多线整合方案】
各话题：旅行 / 读书 / 养猫
话题间的关系：表面上无明显关系，需要寻找统一线索

可能的统一线索：
1. "独处方式"——三件事都是人独处时做的事，可以从"我的独处配方"为统一线索
2. "另一种时间感"——旅行、读书、养猫都能让时间变慢或变快，可以从"时间感"切入
3. 个人叙事——这三件事都发生在"我"身上，用第一人称的个人散文串联，不需要强调逻辑关系

方案 A（主题法："独处的艺术"）：
　统一线索：这三件事都是作者独自享受的方式
　结构顺序：引入"独处"概念→养猫（家中的独处）→读书（思想上的独处）→旅行（空间上的独处）
　过渡策略：每个话题都回到"独处"这个主题词上

方案 B（散文式：用"我"的生活串联，不强调逻辑）：
　统一线索：作者自己的生活切片，不需要明确的逻辑关系
　结构顺序：可以任意，用情感和语气的流动连接
　适合场景：如果这是一篇随笔性质的散文，不需要议论逻辑

推荐：方案 A，因为给读者一个理解"为什么这三件事放在一起"的线索，会让文章更有整体感
注意：如果三个话题每个都想深入展开，篇幅会很长，建议每个话题只展开最有感触的一个细节，不面面俱到
```

## Best Practices

- 整合多话题的前提是找到一个真实的统一线索，不能为了整合而强行拼凑。
- 如果某个话题和其他话题实在无法整合，不要硬塞，单独成篇往往效果更好。
- 整合结构确定后，建议用 `outline-expander` 进一步细化每个话题的内部结构。

## Edge Cases

- **话题超过5个**：建议先做取舍，选最重要的3-4个，其余另开文章。
- **作者不确定想写哪种类型的文章（议论还是散文）**：不同类型的整合方式不同，先用 `purpose-clarifier` 确认目的。
- **话题之间有矛盾（如想说A好，又想说A不好）**：这可能是一篇讨论A的复杂性的文章，参考 `contradiction-resolver` 处理逻辑。
